# Release 0.4.0: tests for every story, fuzz, SDK examples

Date: 2026-11-03. Plan: `docs/prd-release-0.4.md`. Branch `docs/course-eighth-grade`, then PR to main.

## What changed

1. **The written word is under test.** `tests/MMP.AsyncProxy.Tests/CourseFenceTests.cs` reads every ```csharp fence in `docs/course/*.md`, `docs/sdk.md`, and `training/*/README.md`. A fence passes when 90 percent of its code lines appear in a `.cs` file under `src/`, `samples/`, `tests/`, or `training/`, or when it carries `<!-- fence: sketch why -->` on the line above. Before this pass 59 of 107 fences missed. Now: 16 became test bodies in `CourseSnippetTests.cs` (17 tests), 13 were re-aligned to their source file, 17 are marked sketches (decompiler output, modern C# for comparison, a deliberately broken exercise, excerpts from the sibling simulator repo), and the 13 SDK fences became `samples/MMP.AsyncProxy.Sdk`.
2. **SDK examples.** `samples/MMP.AsyncProxy.Sdk/`, one file per section of `docs/sdk.md`, net35, C# 3. `SdkTests.cs` runs each (14 tests).
3. **Sample tests.** `SampleProgramTests.cs` runs the Comparison console as a process (default and `waves`) and the compiler-reference method. Referencing the Comparison project would have put the net48 library beside the net35 one under test, so it runs out of process.
4. **Fuzz.** `tests/MMP.AsyncProxy.Fuzz`: six generators (promise races, iterator programs, combinators, cancel races, delay storm, post-target runs), seeded, with a console runner (`dotnet run -- 60 [seed]`, `-- replay <generator> <seed>`). `dotnet test` runs 8 seeds × 40 rounds per generator.
5. **Runtime fixes.**
   - `IteratorStateMachine<T>.MoveNext`: a throwing `finally` in the body escaped the catch and left the future Pending (found by the 2026-11-03 course review). Now `Dispose` is guarded; the first fault wins; the cleanup fault rides on it under `AsyncProxy.DisposeFaultKey`. README known limit 5 records the difference from the compiler. Tests: `IteratorCleanupTests`.
   - `Futures.WhenAll`: faults were listed in completion order while the README and the SDK guide promised input order. Found by the fuzz suite on its first run. Now one slot per input, no lock. Test: `WhenAllOrderTests`.
   - `DelayWheel`: the one shared timer captured the `ExecutionContext` of whichever thread first armed it, and every delay callback ran under it. Found by reader A. Now the timer is created under `SuppressFlow` and completions use `UnsafeQueueUserWorkItem` (desktop builds).
6. **Test suite serialized.** With the new process-spawning and 64-item tests in flight, the 30 ms wheel test took 1,082 ms under pool starvation and a console-capture test read another test's output. `AssemblyInfo.cs` disables parallelization, as the training suite already did. The other session that merged PR #15 reported the same two flakes on main before this change.
7. **Docs.** README: SDK table, fuzz section, known limit 5, fresh bench and comparison numbers from one 2026-11-03 run, claims qualified per the Iolo audit. `docs/sdk.md` rewritten around the Sdk files. Course and training READMEs corrected per three readers (below).
